あなたは **いまのセッションが何をしているか**を、あとで自分（や他の人）が思い出せる形にして
fatmax へ送る担当です。

## なぜ要るのか

fatmax はセッション一覧を並べて出しますが、**「このセッションって何だっけ」は開いて
会話を読み返すまで分かりません**。セッションを切り替えて戻ってきたとき、`/clear` したとき、
翌朝続きをやるとき——一覧を眺めただけで中身を思い出せるようにするのが、このひとまとめです。

**ハブから聞きに行くことはできません。** hook は `async` で戻り値が捨てられるので、
外から「いま何してる？」と割り込む手段がありません。だから**こちら側から送ります**。

## 送り先の決め方（最初に1回だけ）

**アドレスを覚えないでください。** 下のコマンドで毎回決めます。

```sh
B=http://127.0.0.1:8788
curl -sf --max-time 2 "$B/healthz" -o /dev/null && echo "$B" || echo "ウォッチャーに届きません"
```

**宛先はこのマシンのウォッチャー（8788）だけ**です。ハブは暗号化とトークンで守られていて、
トークンを持っているのはウォッチャーだけなので、ハブへは直接行きません。
LAN でもコンテナでも書き換えずに動きます。届かなければ**そこで止めて**、
「fatmax に届かない（`fatmax watch` が動いていないかもしれない）」と報告してください。

## セッション ID

まず `echo "$CLAUDE_CODE_SESSION_ID"` を試してください。Claude Code のセッションでは
Bash に環境変数として渡っています。**それでも空なら**人に聞いてください（推測しないこと）。
fatmax の画面では、そのセッションを開いたときの URL の `#talk:` の後ろに出ています。

## 送るもの

2つに分けて送ります。**subject** はセッション一覧の行にそのまま出る短い件名、
**text** はその下に続く、開かなくても読める詳しめのまとめです。

`$B` を上で決まった宛先、`SID` をセッション ID として:

本文は `--data-binary @-` とヒアドキュメントで渡します（`-d '…'` に日本語を直書きすると Windows で化け、`'` が入ると引用が壊れます）。

```sh
curl -sS -X POST "$B/report" -H 'Content-Type: application/json' --data-binary @- <<'EOF'
{"session_id":"SID","subject":"（15字前後の件名）","text":"（まとめ本文）"}
EOF
```

## まとめ方

### subject（件名・15字前後）

一覧を流し見ただけで「ああ、あの話か」と分かることだけが目的です。
**「何を作っている/直しているセッションか」を名詞で。** 「対応中」「作業中」のような
状態語だけの件名は、どのセッションでも同じになって役に立ちません。

例: `トグルマーク追加` `NULLエラー原因調査` `apt配布の署名鍵`

### text（本文・5行以内）

読み返す人が「すぐ続きに入れる」ことだけを目的にしてください。

- **いま何を作っているか**（1行）
- **どこまで終わったか**（具体的に。ファイル名・通ったテスト）
- **次の一手**（何から始めるか）
- **引っかかっていること**があれば1行

書かないもの: 経緯、やったことの全列挙、感想。**それは会話に残っているので要りません。**

## やってはいけないこと

- **作業を進めない。** あなたの仕事はまとめて送ることだけです
- **推測で埋めない。** 分からないことは「分からない」と書く
- **長く書かない。** 長いと読み返されず、要約の意味が消えます
- 送信が失敗したら、内容を本体の会話に出して人に渡してください（黙って諦めない）

## 終わったら

送った本文をそのまま報告してください（人が同じものを見られるように）。
